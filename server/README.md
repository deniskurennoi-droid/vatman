# Ватман: сервер

JSON-API для аккаунтов и общих досок. Сайт при этом остаётся статикой на
GitHub Pages и обращается сюда запросами — ссылка на доску не меняется.

Стек нарочно скучный: FastAPI, база SQLite в одном файле, пароли через
`hashlib.scrypt` из стандартной библиотеки. Никаких внешних сервисов, кроме
самого Railway.

## Запуск у себя

```powershell
py -m venv venv
venv\Scripts\python -m pip install -r requirements.txt
venv\Scripts\python -m uvicorn main:app --port 8000
```

Проверить, что всё живо: открыть `http://127.0.0.1:8000/api/health`.

Сквозная проверка — регистрация двух людей, общая доска, приглашение по коду,
правки с двух сторон:

```powershell
$env:VATMAN_API="http://127.0.0.1:8000"; venv\Scripts\python apitest.py
```

## Выкладка на Railway

1. **New Project → Deploy from GitHub repo**, выбрать репозиторий, в настройках
   сервиса указать **Root Directory** = `apps/vatman-server`.
2. **Variables** — добавить:
   - `VATMAN_DB` = `/data/vatman.db`
   - `VATMAN_ORIGINS` = `https://deniskurennoi-droid.github.io`
3. **Volumes → New Volume**, точка монтирования `/data`. Без этого база будет
   стираться при каждой новой выкладке.
4. **Settings → Networking → Generate Domain**. Полученный адрес вписывается
   в сайт как адрес API.

Порт Railway подставляет сам через `$PORT`, команда запуска берётся из `Procfile`.

## Что где

| Файл | Что это |
|---|---|
| `main.py` | весь сервер: вход, доски, объекты, приглашения |
| `apitest.py` | сквозная проверка, 54 утверждения |
| `requirements.txt` | две зависимости |
| `Procfile` | команда запуска для Railway |

## Устройство

Таблицы: `users` (включая личный код приглашения), `sessions`, `boards`,
`members`, `items`.

Объекты доски хранятся **по строке на каждый стикер**, а не одним куском JSON.
Это главное решение: двое, правящие разные стикеры, не затирают работу друг
друга. У каждой доски есть счётчик версии, и каждая правка его увеличивает —
поэтому открытая доска спрашивает «что изменилось после версии N» и получает
только новое. Удалённые объекты остаются в таблице с пометкой `deleted = 1`,
иначе второй участник не узнал бы об удалении.

Свои собственные правки в ответ на такой запрос не возвращаются — иначе доска
дёргалась бы от эха собственных действий.

Честная оговорка: если двое в одну и ту же секунду двигают **один и тот же**
стикер, сохранится правка того, кто нажал позже.

## Безопасность

- Пароли: `scrypt` с n=16384 и личной солью у каждого. В базе нет ни паролей,
  ни чего-либо, из чего их можно восстановить.
- Сессии: в базе лежит отпечаток токена (SHA-256), а не сам токен. Утечка базы
  не даёт войти в чужой аккаунт.
- Личные коды нельзя перебрать: ответ всегда «код есть» или «кода нет»,
  и на приглашения стоит ограничение по частоте.
- Вход и регистрация ограничены по числу попыток с одного адреса.
- Чужие доски закрыты: каждый запрос проверяет, что человек есть в составе
  участников именно этой доски.

## Чего пока нет

- **Письма.** Регистрация сразу пускает в аккаунт, без подтверждения адреса и
  без восстановления пароля — для этого нужен почтовый сервис (Resend). Пока
  это значит, что забытый пароль придётся сбрасывать руками в базе.
- Живое обновление сделано опросом раз в пару секунд, а не постоянным
  соединением. Для доски на нескольких человек этого достаточно.
